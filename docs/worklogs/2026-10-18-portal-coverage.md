# 포털 검색 대조와 수집 엔진 업데이트

## 계약·라우팅

요청: 포털의 청년 관련 검색과 실제 수집의 차이를 분석하고 누락 원인을 수정한다. 완료 기준은 검색 스냅샷, 변경 전후 재현, 수집/분류/공개 경계 구분, 회귀 검증, 실제 재수집·배포 확인이다. 외부 메시지 발송과 무관한 UI·회원 기능 변경은 제외한다.

Always: canonical identity_harness의 AGENTS·Brain·Skill Router. Active: collect-news → dedup-filter → publish, Source, Project Execution, Eval Global/implementation gate. 입력은 현행 source_config·collector·curation·운영 아카이브와 공개 포털 응답이다. 출력은 코드·테스트·대조 스크립트·이 기록과 분리된 runtime 증거다. 인벤토리 드리프트: 색인의 일부 경로와 5월 메뉴 기준은 실제 파일·365일 아카이브와 다르므로 현재 코드가 우선이다. 기존 일간 PICK 기획·웹사이트 재설계·개인 문체·전역 하네스 변경은 제외한다.

## 비교 범위와 해석

- 검색어: `청년`, `청년정책`, `청년 정책`.
- 표본 시각: 2026-10-18 12:56~12:57 KST. 검색 응답은 HTML/XML/JSON과 SHA256으로 별도 보관했다.
- 네이버: 최근 1주, 최신순 첫 화면과 화면에 제시된 더 보기 두 페이지. 90개 노출 슬롯, 검색어/페이지 간 중복을 제거한 URL 51개.
- 구글: 최근 7일 검색 RSS의 각 100건. 300개 슬롯, 중복 URL 213개. 관련도 기반의 제한된 RSS 표본이지 최신순 전체 검색 결과가 아니다.
- 다음: 세 검색어 모두 실제 CAPTCHA 이동 응답. 우회하지 않았고, 0건/수집률 0%가 아닌 `blocked / 비교 불가`다.
- 비교 아카이브: 변경 전 GitHub main의 3,615건, 생성 시각 09:17 KST. 포털 표본은 이후에 관찰했으므로 이후 게시물은 종전 아카이브에 없다는 이유만으로 엔진 누락으로 판정하지 않는다.
- 동일성은 URL 또는 정규화한 정확한 제목 + 확인된 발행사 + 한국시간 게시일로 비교한다. 다른 URL/제목/매체명으로 저장된 경우는 일치를 놓칠 수 있으므로 측정치는 ‘확인된 겹침의 하한’이며 전체 재현율·누락률이 아니다.

구글 각 100건과 변경 전 아카이브의 확인된 겹침은 청년 20건, 청년정책 30건, 청년 정책 34건이다. 각 표본에서 아카이브 생성 시점 이후로 확인되는 1건은 별도 표시했다. 나머지 미일치도 의도적 필터링, URL/제목 차이, 제한된 검색·수집 시점, 수집 오류를 구분해야 한다. 이 숫자만으로 모든 미일치를 장애로 선언하지 않는다.

## 재현된 원인

1. 정상 네이버 페이지의 공통 스크립트에 `captchaApi`가 있다. 이전 접근 판정은 응답 전체의 문자열만 보고 정상 검색을 차단으로 오인했다.
2. 발행사 프로필의 첫 링크가 이미지와 ‘새 창 열림’만 포함한다. 실제 발행사명이 있는 두 번째 링크 대신 접근성 안내를 발행사로 수집했다.
3. 기존 검색 URL의 `start=11/21`은 첫 10건을 반복할 수 있다. 화면의 XLoad URL은 별도의 공개 더 보기 경로이며 JSON의 `collection[].html`에 다음 기사들이 있다.
4. 기본 검색어에서 네이버/구글 모두 붙여쓰기·띄어쓰기의 범위를 별도로 확인할 필요가 있다. 기존 구글 정책 검색은 한 응답에서 최대 30건만 남겼고, 넓은 ‘청년’ 기본 경로도 없었다.
5. 일부 짧은 제목·요약의 ‘청년 … 지원 근거 마련’은 실제 정책 관련 내용인데 직접 도움 신호가 약해 공개 점수 3점으로 탈락했다. 의회 방문·기념사진 등과 구분되는 좁은 규칙이 필요했다.

## 변경

- 접근 판정은 스크립트·스타일·템플릿을 뺀 짧은 화면 문구와 실제 CAPTCHA 이동으로 판단한다. 정상 RSS XML은 기사 본문의 단어 때문에 차단하지 않는다. 실제 차단 우회는 추가하지 않았다.
- 네이버 제목 역할과 발행사 링크를 기준으로 파싱하고 접근성 안내를 제거한다. 옛 headline 구조도 지원한다.
- 화면에서 발견한 XLoad/JSON 다음 경로를 따르되 HTTPS, 지정된 네이버 호스트·뉴스 경로·동일 검색어를 검증한다. 페이지 반복·새 기사 없음·설정 상한에서 중단한다.
- 뒤 페이지가 실패해도 앞에서 얻은 기사는 보존하고 매니페스트에 `partial_result`로 드러낸다.
- 네이버 ‘청년’ 기본 경로의 후보 범위를 넓혔다. 네이버/구글 붙여쓰기 검색과 구글 ‘청년’ 전체 검색을 추가했다. 구글 정책 검색 상한은 30→100이다. 등록 88개·활성 87개, 활성 news 42개다.
- `청년`과 가까운 `지원 근거 / 법적 근거 / 조례 제정 / 조례안`을 직접 정책 신호로 보완했다. 기존 약한 청년성·잡음·선거 공방 판정은 우회하지 않는다.
- 최종 실제 수집물 점검에서 드라마 등장인물의 ‘청년·노동’ 줄거리가 실제 노동 기사로 통과한 사례를 확인했다. 캐스팅·티저·신예스타 등 작품 공개 기사와 허구의 줄거리가 함께 있을 때 공개 후보에서 제외하되, 실제 청년 예술인 지원사업과 정책 보도는 보존한다.
- `public-site/scripts/audit_portal_coverage.py`: 검색 응답 스냅샷, 지정 커밋의 수집/분류 코드와 설정 재생, 경로별 후보·분류·공개 후보·아카이브 대조를 지원한다. 생산 DB·수신자·공개 산출물은 수정하지 않는다.

## 실제 실행과 검증

- 공개 응답을 다시 읽는 기본 검색 6개 경로: 전부 `ok`, 원시 후보 508건(검색어 간 중복 포함). 네이버 청년 112, 붙여쓰기 정책 60, 띄어쓰기 정책 39, 구글 세 경로 각 99건. URL 변화와 시각 차이 때문에 고정 스냅샷의 수와 같을 필요는 없다.
- 위 원시 입력을 별도 경로에서 실제 dedup_filter/run_curator로 처리했다. 214건 분류, 자동 선별·요약 10건, 운영 레이더 77건. 최종 공개 적합 판정은 작품 홍보 1건을 제외한 191건이다. 최종 분류는 `final_classified.json`이며 앞선 `step3.json`의 192건 판정과 구분한다. 주 작업 폴더 DB·production runtime을 덮어쓰지 않았다.
- 배포용 별도 worktree에서 최초 아카이브와 최종 분류 214건을 병합했다. 공개 적합성·중복 정리를 거친 누적 건수는 3,615→3,719이다(중간 3,720건에서 작품 홍보 1건 제외). 이는 기본 포털 6경로의 부분 갱신이며 전체 87개 소스의 새 실행 성공이 아니다.
- 회귀 테스트: 배포 checkout 207개 통과. 정상 검색의 dormant CAPTCHA, 실제 CAPTCHA 이동, 발행사 접근성 안내, JSON 더 보기, 호스트/검색어 이탈, 반복 페이지, 뒤 페이지 실패 보존, 한국시간 날짜·발행사 동일성, 지원 근거와 단순 의회 사진 기사, 허구 줄거리와 실제 예술인 지원을 포함한다.
- Public Site CI와 Institution Site CI는 첫 수집 코드 커밋 `169ccdc`에서 성공했다.
- 전체 소스 재수집 시도 https://github.com/pcwin21-alt/youth-information-hub/actions/runs/39095515495 는 광범위한 소스 실행과 이번 기본 포털 검증을 구분하기 위해 취소했다. 완료된 전체 수집으로 보고하지 않는다. 대신 실제로 성공한 기본 포털 6경로의 원시 입력→분류→아카이브 병합을 배포 데이터로 사용하고 별도 archive-only 렌더 배포를 검증한다. 이 기록 시점에는 최종 배포 확인 전이다.
- 변경 전 사이트의 news.html은 HTTP 200, 12,224,920바이트·제목 2,880개였다. site-data/pipeline_status.json은 9월 5일의 오래된 완료 상태라 최신 수집 증거로 쓰지 않는다. 이 부분 갱신을 전체 수집 시각처럼 덮어쓰지도 않는다.

## 경계와 잔여 위험

포털 전체 결과와 100% 같게 만드는 것이 목표가 아니다. 정책 서비스의 공개 적합성, 원문 우선·전재 통합, 검색 정렬·시점·결과 상한, 네트워크 차단이 다르다. 특히 다음은 이번 환경에서 직접 검색 대조가 막혔으며 별도의 검증 가능한 공식 연동이 없으면 ‘동일함’을 주장할 수 없다. 기존 지자체 소스의 오류와 일부 원문 날짜 미확인도 별도 문제로 남는다.

기존 로컬 변경을 보존하기 위해 원격 main 기준 별도 관리 worktree에서 수정·배포했다. 검토한 변경만 주 작업 폴더에 적용했으며 기존 테스트·UI·기관 사이트 변경은 되돌리지 않았다. 외부 알림·구독 변경·CAPTCHA 우회·가짜 데이터 생성은 하지 않았다.
